(66e8625, the census tools copied in, untracked), then on 6c7c098, which
derives the home seed's filesystem identity.  Each run builds every image in
a fresh, sandboxed store, rebuilds it from the same inputs with --rebuild,
reads both VHDX files back to raw with qemu-img, and has
tools/lib/image-diff.py name the structure each differing byte sits in.
The output below is verbatim; exit=1 means some layer did not reproduce.

How to read it:
  - "payload, in N blocks" is VHDX payload blocks, whose contents are the raw
    disk: the raw comparison below it says where in the disk they differ.
  - "unaccounted" is bytes of the second VHDX past the end of the first, or
    in space the first one's BAT does not reference: the two files are not
    the same size, because the second build allocated blocks elsewhere.
  - The system image's figures move from run to run - how much of the root
    filesystem lands elsewhere is what differs between builds - while the
    share of its non-zero blocks whose content both builds have stays at
    94.2%: the data is the same, its placement and the metadata over it are
    not.
  - The home seed's raw comparison after the change is 0 bytes: the ext4
    filesystem is identical, and what is left is qemu-img's container.
